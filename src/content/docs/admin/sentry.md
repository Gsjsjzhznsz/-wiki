# Sentry 日志监控

> **插件版本**：Sentry-1.5.4-plugin
> **适用服务端**：一秋小镇全部服务器

Sentry 是一秋小镇服务器集群的错误日志监控系统。它自动捕获服务器运行过程中的所有异常、错误和性能数据，并通过 Web 控制台进行可视化展示，帮助管理员快速定位和解决问题。

## 什么是 Sentry？

Sentry 是一个开源的**应用程序错误监控平台**。在一秋小镇的部署中，Sentry 插件将 Minecraft 服务器的运行时错误实时上报到自建的 Sentry 服务器，形成完整的错误追踪体系。

### 监控范围

| 监控类型 | 说明 | 示例 |
|----------|------|------|
| **插件异常** | 任何插件抛出的未捕获异常 | NullPointerException、ClassCastException |
| **服务端错误** | 服务端核心产生的错误 | 内部异常、线程崩溃 |
| **性能监控** | TPS 下降、内存使用异常 | TPS 低于 15、内存超过 80% |
| **定时任务超时** | 插件定时任务执行时间过长 | 主线程阻塞超过 50ms |
| **事件处理错误** | 事件监听器中的异常 | PlayerMoveEvent 处理超时 |

[!TIP]
> Sentry 会在错误发生的第一时间将完整的**堆栈跟踪（Stack Trace）**、服务器状态和上下文信息上报。管理员无需手动翻阅控制台日志即可发现所有错误。

## 核心功能

### 错误捕获与上报

| 功能 | 说明 |
|------|------|
| 自动异常捕获 | 拦截所有未处理的异常并上报 |
| 完整堆栈跟踪 | 记录完整的调用链，快速定位代码位置 |
| 上下文信息 | 附带服务器版本、在线玩家数、内存使用等环境信息 |
| 面包屑（Breadcrumbs） | 记录错误发生前的一系列事件，还原问题现场 |
| 重复错误聚合 | 相同错误自动合并，避免信息过载 |
| 错误分配 | 可将错误分配给特定管理员处理 |
| 状态标记 | 已解决、待处理、忽略等状态管理 |

### 性能监控

| 监控指标 | 说明 | 告警阈值 |
|----------|------|----------|
| **TPS（每秒刻数）** | 服务器主循环频率 | 低于 15 时告警 |
| **MSPT（每刻耗时）** | 每个 Tick 的实际耗时 | 超过 50ms 时告警 |
| **内存使用率** | JVM 堆内存使用百分比 | 超过 80% 时告警 |
| **玩家数量** | 同时在线玩家数 | 用于关联性能问题 |
| **实体数量** | 已加载的实体总数 | 超过阈值时告警 |
| **区块数量** | 已加载的区块数量 | 异常增加时告警 |

[!NOTE]
> 性能监控数据每 30 秒采样一次。当指标超过告警阈值时，Sentry 会创建一条性能事件记录，并在控制台中生成告警通知。

## 插件崩溃报告

当服务器上的某个插件发生崩溃时，Sentry 会自动收集以下信息并生成报告：

| 信息项 | 内容 |
|--------|------|
| 插件名称与版本 | 例如 `EssentialsX 2.20.1` |
| 异常类型 | 例如 `java.lang.NullPointerException` |
| 完整堆栈跟踪 | 从异常抛出点到捕获点的完整调用链 |
| 服务器版本 | 例如 `Paper 1.20.4` |
| Java 版本 | 例如 `OpenJDK 17.0.9` |
| 在线玩家数 | 崩溃时的玩家数量 |
| 系统资源状态 | CPU、内存使用情况 |
| 发生时间 | 精确到毫秒的时间戳 |
| 复现频率 | 该错误在最近 24 小时内的发生次数 |

## 管理员使用指南

### Sentry 控制台

一秋小镇的 Sentry 控制台部署在内部网络，管理员可以通过浏览器访问。

| 控制台功能 | 说明 |
|-----------|------|
| **问题列表** | 查看所有已上报的错误，按严重程度排序 |
| **问题详情** | 查看单个错误的完整堆栈跟踪和上下文 |
| **趋势分析** | 查看错误随时间的变化趋势 |
| **性能仪表盘** | 实时查看 TPS、内存等性能指标图表 |
| **告警规则** | 配置自定义告警条件和通知方式 |
| **版本标记** | 标记错误首次出现的插件/服务端版本 |

### 常用操作流程

#### 排查服务器卡顿

```
1. 打开 Sentry 控制台
   │
   ▼
2. 查看「性能仪表盘」
   │
   ▼
3. 找到 TPS 下降的时间段
   │
   ▼
4. 查看同时段的上报错误
   │
   ▼
5. 定位导致卡顿的插件/事件
   │
   ▼
6. 修复问题并标记为「已解决」
```

#### 处理插件崩溃

```
1. 在问题列表中找到崩溃事件
   │
   ▼
2. 查看完整堆栈跟踪
   │
   ▼
3. 确认是否为已知问题
   │
   ▼
4. 新问题：检查插件更新 / 提交 Issue
   │
   ▼
5. 已知问题：等待更新或临时禁用插件
   │
   ▼
6. 标记处理状态
```

[!TIP]
> Sentry 支持为每个问题设置**分配人**。当某个错误需要特定管理员跟进时，可以将其分配给对应的人员，避免重复排查。

## Sentry 的好处

| 好处 | 说明 |
|------|------|
| **主动发现问题** | 无需等待玩家反馈，错误发生时立即上报 |
| **快速定位根因** | 完整的堆栈跟踪和上下文信息加速排查 |
| **减少宕机时间** | 早期发现问题，在影响扩大前修复 |
| **趋势分析** | 了解服务器的健康状态变化趋势 |
| **团队协作** | 多个管理员可以协同处理问题 |
| **历史记录** | 保留所有历史错误记录，便于回溯 |
| **性能可视化** | 直观的图表展示服务器性能指标 |

[!WARNING]
> Sentry 上报的数据可能包含部分服务器和玩家信息。请勿将 Sentry 控制台的访问权限分享给非管理员人员。所有错误日志应视为**服务器内部信息**，不得公开传播。

## 配置要点

Sentry 插件的配置文件 `plugins/Sentry/config.yml` 核心参数：

| 配置项 | 说明 |
|--------|------|
| `dsn` | Sentry 服务器的数据源名称（DSN），用于上报数据 |
| `environment` | 环境标识，如 `production`、`development` |
| `release` | 版本标识，标记当前服务端/插件版本 |
| `sample-rate` | 采样率（0.0-1.0），控制上报比例 |
| `traces-sample-rate` | 性能追踪采样率 |
| `send-default-pii` | 是否发送默认的个人信息标识 |

[!NOTE]
> 一秋小镇的 Sentry 配置中 `send-default-pii` 设为 `false`，不会在错误报告中包含玩家的 IP 地址等敏感信息，仅记录游戏内用户名用于问题关联。
