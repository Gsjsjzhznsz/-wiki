# vanish++ 隐身管理

> **插件版本**：vanishpp-1.1.8
> **适用服务端**：一秋小镇全部服务器

vanish++ 是一秋小镇服务器的管理员隐身模式系统，允许管理员在玩家不知情的情况下监控服务器。隐身状态的管理员对普通玩家完全不可见、不可交互，是服务器管理工作中不可或缺的工具。

## 什么是 vanish++？

vanish++ 是一个增强版的管理员隐身插件。与原版 Minecraft 的 `/gamemode spectator` 不同，vanish++ 提供了更深层次的隐身效果——不仅视觉上不可见，还在服务器层面完全隐藏管理员的踪迹。

### vanish++ 与原版旁观模式的对比

| 特性 | 原版旁观模式 | vanish++ |
|------|-------------|----------|
| 视觉不可见 | ✅ | ✅ |
| 不在 Tab 列表中显示 | ❌ | ✅ |
| 聊天消息中不可见 | ❌ | ✅ |
| 不可被命令选中 | ❌ | ✅ |
| 不会触发玩家的距离感应 | ❌ | ✅ |
| 可正常与世界互动 | ❌ | ✅ |
| 防止物理碰撞 | ❌ | ✅ |
| 防止被攻击 | ❌ | ✅ |
| 加入/退出服务器无提示 | ❌ | ✅ |

[!TIP]
> vanish++ 的核心理念是**让管理员像不存在一样**。开启隐身后，管理员对普通玩家来说就像是服务器中完全不存在的实体。

## 隐身功能详解

### 隐藏层级

vanish++ 在多个层面隐藏管理员的踪迹：

| 隐藏层面 | 说明 | 技术实现 |
|----------|------|----------|
| **实体隐藏** | 不向其他玩家发送管理员的实体数据包 | 拦截 PacketPlayOutSpawnEntity |
| **Tab 列表隐藏** | 不在玩家列表中显示 | 自定义 Tab 列表渲染 |
| **聊天隐藏** | 隐身管理员发送的消息仅其他管理员可见 | 拦截 AsyncChatEvent |
| **加入/退出隐藏** | 管理员加入或退出时无系统提示 | 拦截 PlayerJoinEvent/QuitEvent |
| **命令隐藏** | 其他玩家无法通过 `/msg`、`/tpa` 等命令选中 | 拦截命令 Tab 补全和执行 |
| **物理隐藏** | 不会与其他玩家发生碰撞 | 移除碰撞实体 |
| **交互隐藏** | 其他玩家无法对隐身管理员使用物品或攻击 | 拦截 PlayerInteractEntityEvent |

### 防检测机制

| 防检测功能 | 说明 |
|---------------|------|
| 距离感应屏蔽 | 不触发其他玩家的「附近有玩家」提示（如果客户端 Mod 有此功能） |
| 光标目标屏蔽 | 其他玩家的准星对准管理员时不显示名字标签 |
| 音效屏蔽 | 管理员产生的声音不对普通玩家播放 |
| 粒子效果屏蔽 | 管理员产生的粒子效果不对普通玩家显示 |
| 追踪盾屏蔽 | 管理员的位置不会出现在追踪道具上 |

[!WARNING]
> 即使 vanish++ 提供了强大的隐藏功能，管理员仍需注意**影子的显示**。在某些光照条件下，隐身玩家的影子可能被其他玩家看到。建议隐身监控时注意自身位置和光照环境。

## 命令列表

### 核心命令

| 命令 | 说明 | 权限 |
|------|------|------|
| `/vanish` | 切换隐身状态 | `vanish.toggle` |
| `/v` | `/vanish` 的简写 | `vanish.toggle` |
| `/vanish on` | 强制开启隐身 | `vanish.toggle` |
| `/vanish off` | 强制关闭隐身 | `vanish.toggle` |
| `/vanish list` | 查看当前所有隐身的玩家列表 | `vanish.see` |
| `/vanish check <玩家>` | 检查指定玩家是否处于隐身状态 | `vanish.check` |
| `/vanish reload` | 重新加载 vanish++ 配置 | `vanish.admin.reload` |

### 高级命令

| 命令 | 说明 |
|------|------|
| `/vanish silentjoin` | 静默加入服务器（加入时即隐身） |
| `/vanish no pickup` | 切换是否自动捡起掉落物 |
| `/vanish no damage` | 切换是否免疫伤害 |

[!TIP]
> 建议管理员将 `/v` 命令绑定到快捷键或使用别名插件进行管理。频繁的隐身切换是日常管理的常见操作。

## 管理员使用指南

### 日常监控

```
1. 静默加入服务器（/vanish silentjoin）
   │
   ▼
2. 以普通玩家的视角观察服务器状态
   │
   ▼
3. 检查玩家行为、建筑、聊天内容
   │
   ▼
4. 发现问题后记录证据（截图/录像）
   │
   ▼
5. 根据情况决定是否解除隐身进行干预
```

### 处理举报

当收到玩家举报时，管理员可以：

1. 隐身传送到被举报玩家附近
2. 暗中观察其行为
3. 确认违规后解除隐身进行处罚
4. 或继续隐身收集更多证据

[!NOTE]
> **处理举报的最佳实践**：在隐身状态下观察至少 3-5 分钟再做出判断。许多举报可能源于误解或偶然情况。充分的观察可以避免误判。

## 与其他插件的集成

| 插件 | 集成方式 | 说明 |
|------|----------|------|
| **LuckPerms** | 权限控制 | 通过 `vanish.*` 权限节点控制访问 |
| **AuthMe** | 登录集成 | 隐身管理员不受 AuthMe 未登录保护影响 |
| **GrimAC** | 反作弊豁免 | 隐身管理员的移动不会被反作弊检测 |
| **PlaceholderAPI** | 变量支持 | 提供 `%vanish_is_hidden%` 等变量 |
| **EssentialsX** | 命令兼容 | 隐身状态下仍可使用 /tp、/god 等管理命令 |
| **dynmap** | 地图隐藏 | 隐身管理员不在 dynmap 上显示 |
| **Tab 插件** | 列表控制 | 与 Tab 列表插件配合，完全隐藏管理员条目 |

[!WARNING]
> vanish++ 需要在插件加载顺序中**优先于**其他交互类插件加载，以确保其隐藏逻辑能够正确拦截事件。如果发现隐身功能不完整，请检查插件的 `plugin.yml` 中的 `softdepend` 或 `loadbefore` 配置。

## 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 隐身后仍被玩家看到 | 插件加载顺序错误 | 在 `plugins/VanishPP/config.yml` 中检查集成配置 |
| 隐身状态在切换世界后失效 | 世界切换触发重新登录 | 重新执行 `/vanish on` |
| 退出后再次加入失去隐身 | 配置中未开启持续隐身 | 检查 `persist-on-rejoin` 配置项 |
| 其他管理员看不到你 | `vanish.see` 权限未设置 | 管理员组需要 `vanish.see` 权限 |
| 被动拾取了地上的物品 | `no-pickup` 未开启 | 执行 `/vanish no pickup` |
| 影子被玩家看到 | Minecraft 客户端渲染限制 | 注意自身光照位置 |
