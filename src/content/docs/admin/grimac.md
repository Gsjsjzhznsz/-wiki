# GrimAC 反作弊

> **插件版本**：grimac-bukkit-2.3.74
> **适用服务端**：一秋小镇主服务器

GrimAC 是一秋小镇服务器的核心反作弊系统，负责检测和拦截各种作弊行为。与传统的基于启发式规则的反作弊不同，GrimAC 采用**基于运动分析（movement analysis）**的检测方式，通过模拟 Minecraft 客户端的物理引擎来判断玩家操作是否合法。

## GrimAC 的工作原理

### 传统反作弊 vs GrimAC

| 特性 | 传统反作弊（如 NoCheatPlus） | GrimAC |
|------|---------------------------|--------|
| 检测方式 | 启发式规则、阈值判断 | 客户端物理模拟 |
| 误判率 | 较高（受网络延迟影响大） | 极低（基于精确模拟） |
| 绕过难度 | 较低（修改客户端即可绕过阈值） | 很高（需要完美模拟原版物理） |
| 性能开销 | 中等 | 较低（单线程预测模型） |
| 更新频率 | 依赖规则更新 | 跟随 Minecraft 版本更新 |

[!NOTE]
> GrimAC 的核心思想是：**在服务端运行一个 Minecraft 客户端的物理引擎副本**。每次玩家移动时，GrimAC 都会模拟一个合法客户端在相同条件下应该如何移动。如果玩家的实际移动与模拟结果不符，则判定为作弊。

## 检测类型

### 移动作弊

| 作弊类型 | 检测名称 | 说明 |
|----------|----------|------|
| **飞行（Fly）** | `PredictionEngine` | 在无创造模式权限时悬浮或飞行 |
| **速度加速（Speed）** | `PredictionEngine` | 移动速度超过合法范围 |
| **长跳（LongJump）** | `PredictionEngine` | 跳跃距离超出合法值 |
| **水舞（Jesus）** | `PredictionEngine` | 在水面行走 |
| **蜘蛛攀爬（Spider）** | `PredictionEngine` | 在没有梯子/藤蔓的墙壁上攀爬 |
| **喷气包（Jetpack）** | `PredictionEngine` | 空中反复跳跃获得高度 |
| **自动疾跑（AutoSprint）** | `NoSlow` | 在不应该自动疾跑时强行疾跑 |
| **慢速下落（NoFall）** | `NoFall` | 跳下高处不受伤 |
| **仿地（AirPlace/GroundSpoof）** | `PredictionEngine` | 伪造地面位置来绕过检测 |
| **滑翔（Glide）** | `PredictionEngine` | 在无鞘翅情况下滑翔 |

### 战斗作弊

| 作弊类型 | 检测名称 | 说明 |
|----------|----------|------|
| **杀戮光环（KillAura）** | `CombatChecker` | 自动锁定和攻击附近实体 |
| **到达距离（Reach）** | `Reach` | 攻击距离超过 Minecraft 允许的最大值 |
| **自动点击器（AutoClicker）** | `ClickProcessor` | 超出人类极限的点击速度 |
| **瞄准辅助（AimAssist）** | `CombatChecker` | 自动修正瞄准角度 |
| **背后击打（BackHit）** | `CombatChecker` | 在不面向目标时发动攻击 |

[!WARNING]
> KillAura 和 Reach 是一秋小镇**零容忍**的作弊行为。一旦检测到此类作弊，系统将自动执行封禁，且申诉成功率极低。

### 其他作弊

| 作弊类型 | 说明 |
|----------|------|
| **快速放置（FastPlace）** | 方块放置速度超出正常值 |
| **自动吃食物** | 自动使用物品恢复生命 |
| **自动钓鱼** | 自动完成钓鱼动作 |
| **X 光（X-Ray）** | 透视地下矿物（由 Orebfuscator 配合检测） |
| **物品修改** | 使用非法附魔或物品 |

## 误判（False Positive）处理

虽然 GrimAC 的误判率极低，但在某些网络条件下仍可能出现误判。

### 常见误判场景

| 场景 | 原因 | 处理方式 |
|------|------|----------|
| 高延迟（200ms+） | 网络波动导致运动数据不连续 | GrimAC 具备延迟补偿，一般不会误判 |
| 坐骑/宠物交互 | 实体碰撞体积计算差异 | 已内置处理逻辑 |
| 传送后短暂检测异常 | 位置突变触发电机检查 | 传送后短暂豁免期 |
| 活塞/红石机关 | 复杂物理交互 | 需要管理员手动标记区域 |
| 末地珍珠传送 | 瞬移导致运动中断 | 已特殊处理 |

[!TIP]
> 如果你在正常游戏时被系统判定为作弊并踢出，请立即联系管理员。管理员会查看后台日志判断是否为误判，如果是误判会立即解除处罚。请保留被踢出前正在进行的操作信息，便于管理员排查。

### 管理员误判处理流程

```
玩家反馈被误判
    │
    ▼
管理员查看 GrimAC 日志
    │
    ▼
确认检测类型和 VL 值 ──▶ 低 VL 值（1-5）──▶ 可能是网络问题，解除处罚
    │
    ▼ 高 VL 值且持续触发
    │
    ▼
分析玩家运动数据 ──▶ 数据确实异常 ──▶ 维持处罚
    │                └─ 数据正常 ──▶ 确认为误判，解除处罚并上报
```

## 检测等级与处罚

GrimAC 使用 **VL（Violation Level，违规值）** 系统来衡量作弊严重程度：

| VL 范围 | 等级 | 处罚措施 |
|----------|------|----------|
| 0 - 10 | 提醒 | 仅记录日志，不执行处罚 |
| 11 - 30 | 警告 | 记录日志 + 取消本次违规操作 |
| 31 - 60 | 严重 | 取消操作 + 警告提示玩家 |
| 61+ | 危险 | 自动踢出服务器 |
| 持续高危 | 封禁 | 自动临时封禁并通知管理员 |

[!WARNING]
> VL 值会在玩家正常游戏时**逐渐衰减**。偶尔的误判不会导致封禁。只有**持续触发**检测的玩家才会被处罚。封禁决定最终由系统和管理员共同确认。

## 玩家须知

### 禁止使用的 Mod/客户端

以下类型的 Mod 可能被 GrimAC 检测并标记为作弊：

| 类型 | 示例 | 风险 |
|------|------|------|
| 战斗辅助 Mod | Reach、KillAura、AutoClicker | ⛔ 直接封禁 |
| 移动辅助 Mod | Fly、Speed、NoFall、Jesus | ⛔ 直接封禁 |
| 视觉 Mod（部分） | X-Ray、ESP、Tracers | ⛔ 直接封禁 |
| 优化 Mod（安全） | OptiFine、Sodium、Lithium | ✅ 允许使用 |
| 小地图 Mod（部分） | JourneyMap（无实体雷达） | ✅ 允许使用 |
| 小地图 Mod（危险） | VoxelMap（带实体/玩家雷达） | ⚠️ 可能被标记 |
| 操作辅助 | Macro/连点器、自动钓鱼 | ⛔ 直接封禁 |
| HUD Mod | REI、JEI、Shulker Box Tooltip | ✅ 允许使用 |

[!TIP]
> **安全使用 Mod 的原则**：只使用不修改游戏机制的 Mod（如纯视觉优化、物品管理）。任何提供游戏机制优势的 Mod 都有被检测的风险。不确定时，先咨询管理员再使用。

### 申诉流程

如果认为被封禁是误判，请按以下流程申诉：

1. 加入一秋小镇 QQ 群或 Discord
2. 私信管理员，提供你的**游戏用户名**和**被封禁时间**
3. 描述被踢出前正在进行的活动
4. 等待管理员查看日志后回复

## 管理员命令

| 命令 | 说明 |
|------|------|
| `/grim alerts` | 开启/关闭作弊检测实时警报 |
| `/grim profile <玩家>` | 查看玩家的违规记录和 VL 详情 |
| `/grim spectate <玩家>` | 以旁观者模式观察指定玩家 |
| `/grim reload` | 重新加载 GrimAC 配置 |
| `/grim debug <玩家>` | 开启指定玩家的调试输出 |
| `/grim setback` | 手动将玩家回退到上一个合法位置 |

[!NOTE]
> `/grim alerts` 命令建议管理员在日常管理中保持开启。当检测到高危作弊时，系统会在管理员聊天中实时推送警报信息。
