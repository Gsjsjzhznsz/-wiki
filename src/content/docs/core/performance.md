# 性能监控与优化

一秋小镇部署了多层性能优化与监控方案，从区块预生成、动态性能监控、后台优化到网络层数据包处理，形成了一套完整的性能保障体系。这些工具协同工作，确保服务器在高负载下依然维持稳定的 20.0 TPS。

## 优化方案总览

| 插件 | 类别 | 核心功能 | 作用层级 |
|------|------|----------|----------|
| **Chunky** | 区块预生成 | 提前生成区块，消除运行时生成卡顿 | 世界/区块层 |
| **DynRegionPerf** | 动态监控 | 按区域实时监控 TPS 和性能指标 | 区域/线程层 |
| **PerfoBooster** | 后台优化 | 自动执行后台性能优化任务 | 系统层 |
| **packetevents** | 网络优化 | 高性能数据包拦截与处理 | 网络/协议层 |
| **Sentry** | 错误监控 | 异常自动捕获与上报 | 应用层 |

## Chunky — 区块预生成

Chunky 是一秋小镇性能优化的第一道防线。它允许管理员在服务器低负载时段（如维护窗口期）**提前生成**玩家活动区域的区块。

### 为什么需要预生成？

当玩家探索新区域时，服务端需要实时生成区块，这个过程涉及地形生成、结构生成（村庄、矿洞等）、生物群系计算等密集运算。在玩家移动过程中频繁生成区块会导致 TPS 剧烈波动。Chunky 通过提前完成这些工作，将运行时的区块生成压力降为零。

### 预生成策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 出生点区域 | 优先预生成出生点周围 1024×1024 区块 | 新玩家首屏加载 |
| 主城区域 | 预生成主城及周边区域 | 高频活动区域 |
| 交通路线 | 沿主要道路和铁路预生成 | 减少旅行时卡顿 |
| 玩家聚集区 | 定期扩展活跃玩家周边区块 | 动态扩展 |

[!TIP]
> Chunky 的预生成任务会在后台低优先级运行，不会影响在线玩家的游戏体验。但如果服务器满载，预生成速度会自动降低以让出资源给在线玩家。

## DynRegionPerf — 动态区域性能监控

DynRegionPerf 是专为 Folia 多线程架构设计的性能监控工具。由于 Folia 将世界划分为多个独立区域，传统的全服 TPS 监控已经无法准确反映每个区域的实际运行状况。

### 监控指标

| 指标 | 说明 |
|------|------|
| 区域 TPS | 每个独立区域的 Tick 速率 |
| 实体数量 | 各区域内的实体总数 |
| 区块加载量 | 各区域的已加载区块数 |
| 红石活跃度 | 各区域的红石信号更新频率 |
| 线程队列延迟 | 区域线程的任务队列积压情况 |

[!NOTE]
> 管理员可以通过 DynRegionPerf 精确定位性能瓶颈所在的区域。例如，如果某个区域的 TPS 降至 18.0，而其他区域保持 20.0，管理员可以针对性地检查该区域的实体数量或红石机器，而不是对全服进行不必要的优化。

## PerfoBooster — 后台优化

PerfoBooster 在服务器运行过程中持续执行后台优化任务，包括但不限于：

- **内存管理优化**：定期整理内存碎片，减少 GC（垃圾回收）停顿。
- **无效实体清理**：自动移除掉落物品、箭矢等无效实体，减轻 Tick 压力。
- **区块卸载优化**：智能判断并卸载不再需要的已加载区块，释放内存。
- **异步任务调度**：将非关键任务转移到异步线程执行，减少主线程压力。

[!WARNING]
> PerfoBooster 的清理逻辑经过严格调优，不会误删玩家放置的物品或重要实体。如果发现异常情况，请立即联系管理团队。

## packetevents — 网络数据包优化

packetevents 提供了高性能的网络层数据包拦截和处理能力，是一秋小镇网络优化的核心组件。它通过 NMS（net.minecraft.server）层直接操作数据包，避免了 Bukkit API 的性能开销。

### 优化效果

| 优化项 | 效果 |
|--------|------|
| 数据包处理延迟 | 降低 30%~50% 的处理开销 |
| 反作弊数据采集 | 为安全系统提供低延迟的包级数据 |
| 协议兼容辅助 | 配合 Via 系列进行高效协议转换 |
| 网络带宽优化 | 减少不必要的数据包发送 |

## Sentry — 错误监控与上报

Sentry 是一个生产级的错误监控平台，一秋小镇将其集成到服务端，实现异常的自动捕获、聚合和上报。

### 监控范围

| 错误类型 | 处理方式 |
|----------|----------|
| 插件异常 | 自动捕获堆栈信息并归类 |
| 服务端崩溃 | 记录崩溃前的最后状态和线程信息 |
| 性能异常 | TPS 持续低于阈值时触发告警 |
| 协议错误 | Via/Geyser 的协议翻译异常 |

[!TIP]
> Sentry 的监控数据仅服务管理团队用于问题排查和性能优化，不会收集任何玩家的个人隐私信息。所有异常日志均经过脱敏处理。

## 协同工作流程

```
玩家连接 → packetevents（高效数据包处理）
    ↓
区块加载 → Chunky（预生成区块，零延迟加载）
    ↓
区域 Tick → DynRegionPerf（实时监控各区域性能）
    ↓
后台任务 → PerfoBooster（持续优化系统资源）
    ↓
异常捕获 → Sentry（自动上报错误，快速修复）
```

这套完整的性能保障体系确保一秋小镇能够在高玩家数量、复杂红石机器和跨平台连接的多重负载下，依然提供流畅稳定的游戏体验。
