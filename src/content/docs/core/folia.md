# Folia 多线程内核

一秋小镇服务器基于 **Folia** 内核运行，这是 PaperMC 团队推出的革命性多线程服务器端软件。与传统的 Paper 和 Spigot 采用单线程主循环不同，Folia 将世界划分为多个独立的 **区域线程（Region Thread）**，每个区域在自己的线程上独立运行游戏逻辑，从而充分利用现代多核 CPU 的性能。

## Folia 与传统内核对比

| 特性 | Spigot | Paper | Folia |
|------|--------|-------|-------|
| 游戏主循环 | 单线程 | 单线程 | 多线程（按区域划分） |
| 实体处理 | 全服共享主线程 | 全服共享主线程 | 按区域分配独立线程 |
| 区块加载/Tick | 串行执行 | 串行执行 | 并行执行 |
| CPU 多核利用率 | 低 | 低 | 高 |
| 大型红石机器表现 | 易卡顿 | 较好但仍受限 | 显著改善 |
| 百人同屏表现 | 严重掉TPS | 可维持但波动大 | 稳定维持 20.0 TPS |
| 插件兼容性 | 极高 | 高 | 需要适配 Folia API |

## 工作原理

Folia 的核心思想是将世界按 **区域（Region）** 进行划分。每个区域包含一定范围的区块，拥有独立的 Tick 循环。当玩家或实体在不同区域活动时，它们的事件处理会被分发到对应的区域线程，互不干扰。

### 区域划分机制

- **区域大小**：Folia 会根据世界类型和负载自动调整区域的大小和数量。
- **线程调度**：每个区域线程拥有独立的 Tick 循环，按固定时间片执行方块、实体、红石等逻辑。
- **跨区域交互**：当实体跨越区域边界时，Folia 会自动将其迁移到目标区域的线程中，确保线程安全。

## 核心优势

### 1. 红石机器性能

一秋小镇中存在大量复杂红石装置。在传统单线程内核中，红石信号的更新是串行的——一个大型红石机器的单次 Tick 可能需要消耗数毫秒甚至更长时间，直接拖慢整个服务器的 TPS。而在 Folia 中，不同区域的红石机器在各自线程上 **并行计算**，彼此不会互相影响。

### 2. 高玩家承载力

当大量玩家集中在不同区域时，Folia 可以将负载分散到多个 CPU 核心上。这意味着即使某个区域出现了短暂的卡顿，也不会影响到其他区域的玩家体验。服务器的整体 TPS 能够稳定维持在 **20.0 TPS**。

### 3. 扩展性

随着服务器玩家数量和建筑复杂度的增长，Folia 的多线程架构能够更好地横向扩展性能，相比单线程内核有更明显的天花板优势。

[!TIP]
> 如果你在一秋小镇中感觉到某个区域偶尔有短暂延迟，这可能是该区域内的红石或实体计算量较大。由于 Folia 的隔离机制，这种延迟**不会扩散到其他区域**，你可以放心继续游玩其他区域。

## 插件兼容性说明

Folia 由于改变了 Bukkit/Spigot 的核心调度模型，部分未适配 Folia API 的插件可能无法正常工作。一秋小镇已对所有核心插件进行了 Folia 兼容性验证，确保正常运行。

| 兼容状态 | 说明 |
|----------|------|
| ✅ 完全兼容 | 插件已使用 Folia 的 RegionScheduler API 进行适配 |
| ⚠️ 部分兼容 | 核心功能正常，部分次要功能可能受限 |
| ❌ 不兼容 | 插件依赖单线程模型，无法在 Folia 上运行 |

[!WARNING]
> 如果你是服务器管理员，在为一秋小镇安装新插件时，请务必确认该插件已声明支持 Folia。未适配的插件可能导致服务器崩溃或数据异常。可以在插件的发布页面或源码中查找 `Folia` 相关的兼容性声明。

[!NOTE]
> Folia 目前仍在活跃开发中。一秋小镇会持续跟踪 Folia 的版本更新，确保内核始终运行在最新稳定版本上，以获得最佳的性能和稳定性。
